תרשים 2

סטטוסים ומה הם מאפשרים בממשק

הקליינט לעולם לא שולח סטטוס. הוא רק קורא אותו ומחליט אילו כפתורים להציג.

דיווח אבדה (LostReport)

Open— approve →Returned

Open: מציגים עריכה, מחיקה, התאמות, "זה שלי".
Returned: קריאה בלבד. התאמות ריקות.

פריט שנמצא (FoundItem)

Available— approve →Returned

משתמש רגיל רואה רק Available. לאדמין: פריט Returned אי אפשר למחוק, אז מסתירים את כפתור המחיקה.

בקשת בעלות (OwnershipRequest)

Pending→Approved/Rejected

רק בקשה Pending מקבלת אצל האדמין כפתורי אישור ודחייה. ב-Rejected מציגים את rejectionReason.

אפיון

אפיון מסכים

לכל מסך: מה מציגים, אילו קריאות API הוא עושה, אילו כפתורים יש ומתי, ואילו שגיאות צריך לטפל בהן.

התחברות והרשמה

ציבורי
/login · /register
מה מציגים
טופס אימייל + סיסמה. בהרשמה גם שם מלא. סיסמה 8 תווים לפחות.
קריאות
POST /auth/login {email,password}POST /auth/register {fullName,email,password}
אחרי הצלחה
שומרים token ו-user. מעבירים לפי user.role: User ל-/my-reports, Admin ל-/admin/requests.
שגיאות

  • 409 בהרשמה: האימייל תפוס
  • 429: יותר מדי ניסיונות, לנסות בעוד כמה דקות

כללי אפליקציה

מה כל האפליקציה צריכה לעשות

התחברות ושמירת מצב

  • שומרים את ה-token ב-localStorage.
  • בטעינת האפליקציה, אם יש token: GET /auth/me. אם חוזר 401, מוחקים ומעבירים ל-/login.
  • התפקיד נלקח מ-user.role שחזר מהשרת.
  • התנתקות = מחיקת ה-token בקליינט. אין endpoint לזה.

קריאות לשרת

  • כתובת השרת במשתנה סביבה: VITE_API_URL.
  • מקום אחד שמוסיף את Authorization לכל בקשה.
  • כל תגובת 401 מכל מקום: התנתקות ומעבר ל-/login.
  • ב-Render הבקשה הראשונה יכולה לקחת כחצי דקה. כדאי מצב טעינה.

הגנה על מסכים

  • מסך מוגן אחד שבודק "מחובר", ואחד שבודק גם תפקיד.
  • תפריט שונה ל-User ול-Admin.
  • השרת בודק הרשאות בכל מקרה. ההסתרה בקליינט היא רק לחוויית משתמש.
חוזה ה-API

טיפוסי TypeScript לתשובות השרת

המבנים המדויקים שהשרת מחזיר. אפשר להעתיק לקובץ types.ts בקליינט. תאריכים מגיעים כמחרוזת ISO.

export type Role = 'User' | 'Admin';
export type LostReportStatus = 'Open' | 'Returned';
export type FoundItemStatus = 'Available' | 'Returned';
export type OwnershipRequestStatus = 'Pending' | 'Approved' | 'Rejected';

export interface User { id: number; fullName: string; email: string; role: Role; createdAt: string }
export interface AuthResponse { token: string; user: User }

export interface Lookup { id: number; name: string }
export interface Lookups { categories: Lookup[]; colors: Lookup[]; locations: Lookup[] }
export type LookupType = 'categories' | 'colors' | 'locations';

export interface Page<T> { items: T[]; total: number; page: number; pageSize: number }

export interface LostReport {
  id: number; title: string; description: string;
  category: Lookup; color: Lookup; location: Lookup;
  lostDate: string; status: LostReportStatus; createdAt: string;
  owner: { id: number; fullName: string };
}

export interface FoundItem {
  id: number; title: string; description: string;
  category: Lookup; color: Lookup; location: Lookup;
  foundDate: string; verificationQuestion: string;
  status: FoundItemStatus; createdAt: string;
  verificationAnswer?: string;            // Admin only
}

export interface Match {
  foundItem: FoundItem; score: number;
  breakdown: { category: boolean; color: boolean; location: boolean };
}

export interface OwnershipRequest {
  id: number; status: OwnershipRequestStatus;
  verificationQuestion: string; answer: string;
  rejectionReason: string | null; reviewedAt: string | null; createdAt: string;
  lostReport: { id: number; title: string; status: LostReportStatus };
  foundItem: { id: number; title: string; status: FoundItemStatus };
  correctAnswer?: string;                                 // Admin only
  user?: { id: number; fullName: string; email: string }; // Admin only
}

// Bodies the client sends
export interface LostReportInput { title: string; description: string; categoryId: number; colorId: number; locationId: number; lostDate: string }
export interface FoundItemInput extends Omit<LostReportInput, 'lostDate'> { foundDate: string; verificationQuestion: string; verificationAnswer: string }
export interface CreateOwnershipRequestInput { lostReportId: number; foundItemId: number; answer: string }

export interface ApiError { error: { code: string; message: string; details?: { path: string; message: string }[] } }
